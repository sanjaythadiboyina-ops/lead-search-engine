PROJECT REQUIREMENTS — LEAD SEARCHING ENGINE
================================================

IMPORTANT:
This is an existing working Lead Searching Engine project.

DO NOT rebuild the project from scratch.
DO NOT remove or break existing working features.
Extend the existing frontend, backend, database, authentication,
lead search, AI analysis, groups, history, and export functionality.

================================================
1. EXISTING CORE FUNCTIONALITY
================================================

The application is a lead-generation / business lead searching website.

Existing functionality includes:

- User signup
- User login
- User logout
- JWT authentication
- User-specific data
- PostgreSQL database
- Business lead search
- City-based search
- Category-based search
- Lead result limit
- Current LatLng Places API integration
- City geocoding
- Nearby business search
- Lead saving
- Duplicate prevention
- Search history
- Lead groups
- Bulk add leads to groups
- Lead status management
- Excel export
- Gemini AI lead analysis
- Lead score
- Lead type
- AI recommendation
- AI reason

Preserve all existing functionality.

================================================
2. MAIN PROJECT GOAL
================================================

Transform the current Lead Searching Engine into a stronger
multi-source lead discovery and enrichment platform.

The system must not depend on only one lead-data provider.

The architecture must allow additional legal/authorized data
providers to be added later without rewriting the whole application.

================================================
3. MULTI-SOURCE LEAD SEARCH
================================================

Create a provider-based lead search architecture.

Current provider:
- LatLng Places

Add support for additional legal/authorized business-data providers
through separate provider modules.

Requirements:

- Provider abstraction layer
- Provider fallback
- Provider-specific error handling
- Provider-specific rate-limit handling
- Merge results from multiple providers
- Deduplicate results
- Store the original source/provider for every lead
- Never claim third-party data as our own data

Do NOT bypass authentication, CAPTCHA, paywalls, API restrictions,
or provider security mechanisms.

================================================
4. CUSTOM KEYWORD SEARCH
================================================

Currently the application mainly searches by city and predefined category.

Add custom keyword/business-type search.

Examples:

- Digital Marketing Agency
- Web Design Company
- Software Company
- Real Estate Broker
- Dentist
- Restaurant
- Gym
- Photography Studio

User should be able to enter a custom keyword.

Keep the existing category system as well.

Search should support:

City + Category

OR

City + Custom Keyword

================================================
5. CITY-WIDE SEARCH
================================================

Current implementation uses a limited geographic radius.

Improve the architecture so larger city-wide searches are possible.

Requirements:

- Geographic search zones/grid
- Pagination
- Multiple nearby search areas
- Avoid duplicate results between areas
- Configurable search radius
- Configurable maximum results
- Respect provider limits and rate limits

The system must not incorrectly mix businesses from unrelated cities.

================================================
7. WEBSITE DATA ENRICHMENT
================================================

Add optional lead enrichment using business websites when legally
and technically permitted.

Only process publicly available information that the target website
allows automated access to.

Possible enrichment:

- Public email address
- Public phone number
- Official website
- Public social links
- Public business information

Requirements:

- Respect robots.txt where applicable
- Respect website terms and access restrictions
- Respect rate limits
- Use reasonable request throttling
- Do not bypass CAPTCHA
- Do not bypass login
- Do not bypass paywalls
- Do not access private information
- Do not scrape restricted/private content
- Store enrichment source URL
- Store enrichment timestamp

================================================
8. SMART DEDUPLICATION
================================================

The same business may appear from multiple sources.

Merge duplicates using reliable signals such as:

- Provider place ID
- Website domain
- Phone number
- Business name
- Address
- Geographic proximity

Do not create multiple duplicate leads unnecessarily.

If the same business is found by several providers,
combine available non-conflicting information and preserve
source/provider information.

14. AI LEAD ANALYSIS
================================================

Keep Gemini AI integration.

AI analysis must be evidence-based.

- Score leads based only on available evidence

- Provide lead type

- Medium Potential

15. SOURCE TRANSPARENCY
================================================

Every lead must show where its information came from.

Example:

Source:
- LatLng Places
- Another authorized provider
- Business Website Enrichment

Do not hide the source.

================================================
16. SECURITY
================================================

Security requirements:

- Keep API keys only in backend environment variables
- Never expose API keys in frontend JavaScript
- JWT authentication
- User-specific lead access
- User-specific groups
- User-specific search history
- Input validation
- Provider rate-limit protection
- Basic abuse protection
- Secure error handling

A user must never be able to access another user's private saved leads.

================================================
17. ERROR HANDLING
================================================

Handle:

- Invalid API key
- Provider unavailable
- Provider timeout
- Provider rate limit
- No search results
- Database unavailable
- AI API unavailable
- Invalid city
- Invalid category
- Invalid search keyword
- Network errors

Show clear user-friendly messages.

Do not expose sensitive backend/API details to users.

Example future sources:

- Authorized places API
- Authorized business directory API
- Other licensed business-data providers

Only integrate sources whose API/data usage permissions allow our use case.

================================================
23. IMPORTANT LEGAL / COMPLIANCE RULE
================================================

The system must only collect and process data through sources and
methods that are legally permitted and authorized for the intended use.

Do not:

- Bypass CAPTCHA
- Bypass login
- Bypass paywalls
- Bypass API restrictions
- Circumvent anti-bot protections
- Collect private information
- Harvest restricted personal information
- Pretend to be an authorized API client

Prefer official APIs, licensed datasets, or permitted public data.
